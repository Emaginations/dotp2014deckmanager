# 万智牌 2014 卡组管理器（dotp2014deckmanager）

> 给《Magic: The Gathering — Duels of the Planeswalkers 2014》用的**卡组管理器**：
> 浏览 21,386 张卡、按关键词/颜色/稀有度筛选、悬浮放大看整张卡面、组卡存盘，
> 还能**直接读写游戏里的牌组**、把自制卡包**打包成 WAD 装进游戏**。
>
> 卡面不是截图，是**用游戏自带的卡框素材实时拼出来的 HTML** —— 放大多少倍都锐利。

---

## 快速开始

### 方式一：下载现成的 exe（推荐）

去 [Releases](https://github.com/Emaginations/dotp2014deckmanager/releases) 下载
`dotp2014deckmanager.exe`，**放到任意一个文件夹里双击**即可，免安装。

首次启动会**静默约 40 秒**（在扫你的游戏目录、建索引），之后启动就很快了。
索引、缩略图缓存、你的卡组工程都会放在 **exe 旁边**，所以别把它塞进
`C:\Program Files`（那里不可写）。

**第一次用要先指游戏目录**：点右上角 ⚙ **设置** → 选《Magic 2014》的安装目录
（里面应该有 `DATA_CORE.WAD`）→ 点「重建索引」。

### 方式二：从源码跑

```bash
pip install pywebview fastapi uvicorn pillow numpy pypinyin
cd frontend && npm install && npm run build && cd ..
python backend/main.py            # 开窗口
python backend/main.py --browser  # 只起服务，自己开浏览器（调前端方便）
```

打包成单文件 exe：

```bash
python build_exe.py               # 会先 npm run build 再 PyInstaller
```

### 环境要求

- Windows（pywebview 走系统自带的 **WebView2**，Win10/11 一般都有）
- 一份《Magic 2014》的安装（Steam AppID `213850`）
- 可选：社区卡包 [Community Wad](https://www.dropbox.com/sh/...)（卡池从 1 万张涨到 2 万多张）

## 怎么跑

上面「方式二」是最短的路径。下面是开发时会用到的开关：

```bash
cd backend
python main.py --browser      # 只起服务，自己开浏览器（调前端方便）
python main.py --debug        # 开 devtools
python main.py --reindex      # 起来之前强制重建索引
python tools/rebuild.py       # 单独建索引（首次约 40 秒，之后按 WAD 指纹自动跳过）
python tools/rebuild.py --check   # 只看索引新不新，什么都不建
```

改前端：

```bash
cd frontend
npm run dev                   # 开发服务器，热更新（后端要另开）
npm run build                 # 产物给后端托管 —— **打包 exe 前必须先跑这个**
```

自检（都不碰游戏目录）：

```bash
python cardset.py             # 卡池查询 + 颜色筛选逐张验证
python packer.py              # XML 生成 + 建包 + magic
python artgen.py              # 封面/立绘尺寸 + TDX 头部
python wadtools.py --selftest # .bsf 检测器（干净的不误报 / 坏包能检出）
```

### 游戏目录

**不写死**。配置在 `data/settings.json`：

```json
{ "game_dir": "E:\\game\\Magic 2014" }
```

改了目录后，四个索引会按新目录的 **WAD 指纹**（每个包的大小 + mtime）自动判断要不要重建 ——
没变就直接读缓存（秒级），变了才重建。

- **悬浮任一卡牌**：约 140ms 后在指针旁边弹出放大卡面，**贴边自动翻到另一侧**。
  卡面上的文字是真的 HTML 文本 —— 放大后依然锐利，可以选中复制。

    → 加载第 15925~16100 张那一页（offset = ⌊16067/175⌋×175）
    → 滚到它 + 闪一圈
  ```

  这一页顶上会显示一条「已跳到第 15926 张开始显示」+ **「回到开头」**按钮 ——
  跳过去之后上面的页没加载，往上滚是空的，得留条退路。
  如果那张卡**不符合当前筛选条件**（比如筛了红色但它不是），会提示而不是默默不动。
- **右上角 ⚙ 设置**：游戏目录 / 索引 / WAD 备份 / `.bsf` 修复 / 诊断日志，五块。

### 撤销 / 重做

顶栏**最左边**两个图标按钮，`Ctrl+Z` 撤销、`Ctrl+Alt+Z` 重做。

- 覆盖所有改牌动作：加牌、加减张数、移除、拖拽删除、**改名**
- **改名按「一次输入」合并** —— 连着打十个字只算一步，否则要按十几次 `Ctrl+Z` 才退得掉
- 换卡组（打开别的工程 / 打开游戏牌组 / 新建）会**清空历史**，撤销不会跨卡组
- 栈深 200 步；鼠标悬停按钮能看到「还能退 N 步」
- 焦点在输入框里时**不拦截** `Ctrl+Z`，交给浏览器做文本撤销

### 规则文本里的法术力符号

`{R}` `{T}` `{2}` 会渲染成游戏自带的符号图。但**素材是 2013 年的 DotP 2014 自带的**，
社区包里有 26 种符号**根本没图**（共出现 638 次）：

| 符号 | 次数 | 情况 |
|---|---|---|
| `{C}` 无色 | 333 | 2016 年 OGW 才引入，游戏早于它 |
| `{E}` 能量 | 247 | 2016 年卡拉德许才引入 |
| `{U/G}` `{R/U}` 混血 | 15 | **有图，但名字反了** —— 见下 |
| `{2/W}` 等 twobrid、`{S}` 雪 | 32 | 游戏没实现 |

两个修法：

1. **混血符号顺序**：素材按游戏的规范顺序命名（`mana_gu`、`mana_ur`），
   卡片 XML 里写 `{U/G}` `{R/U}` 是反的。现在**两种顺序都试**。
2. **没图的退回「圆底字母」**（黑底 + 白字的小圆点），不是裂图也不是裸花括号。

> [!IMPORTANT] 为什么不能凭文件名猜
> 前端原来的判断是「文件名非空」，`{C}` 会算出个 `mana_c` 一路送到 `<img>`，
> 结果卡面上一个**裂图图标**。现在启动时先拉 `/api/framelist` 拿到**真实存在的
> 素材清单**，不在清单里的直接走兜底；再加上 `<img onError>` 双保险 ——
> 清单没到或者对不上，也绝不会在卡面上留裂图。

#### 检测并修复 `.bsf` —— 治那个「启动几秒后随机崩溃」

`.bsf` 是 UI 文字表。引擎的解析循环**只检查「条目起点」是否在缓冲区内，不检查数据本身**：

```asm
0x70a3d9  cmp ebx, [ebp-0x44]      ; 起点 < 尾 ?
0x70a3dc  jb  0x70a180
0x70a180  mov al, byte [ebx]       ; 逐字节扫 0x00
0x70a182  inc ebx
0x70a185  jne 0x70a3d9
; ---- 出循环，ebx 指向 NUL 之后 ----
0x70a18b  movzx ecx, word [ebx+1]  ; ★ 读 valLen —— 没有边界检查
0x70a18f  mov al, byte [ebx]       ; ★ 读 keyLen —— 同样没有
```

**起点在界内 ≠ 数据在界内。** 文件末尾多一个孤立的 `0x00`，循环就会再进一次、
把 `ebx` 推到缓冲区尾，这两条读指令落到**缓冲区外 3 字节**。读到的垃圾被当成
`valLen` 去拷 —— 内存可读时无害，**一旦缓冲区顶在已提交页边界上就是 ACCESS_VIOLATION**。

这解释了「**约 40% 概率、启动 4 秒后随机崩溃**」：堆布局随装了哪些包而变，
缓冲区落点也跟着变，所以改 WAD 会影响崩溃率。

`DATA_DECKS_D910.WAD`（中文包）的 9 个 `.bsf` 历史上就各多了一个尾部 `0x00`
（`DATA_CORE` 里的同名文件是干净的，说明是那个包制作时引入的）。

**设置 → 扫描** 会遍历所有 WAD 里的 `.bsf`（91 个），列出会越界读的；
**修复** 把多余的尾部字节删掉。和写回牌组一样走 `Wad.rebuild()`，写前自检、
自动备份、写后复验 `headerXml` 和目录数没变。

> 那 9 个字节在 `dotp2014decks` 里已经修过了，所以现在扫应该是「全部干净」。
> 这个功能留着是给**将来装了别的包又出问题**时用的。

检测逻辑有自测（`python wadtools.py --selftest`）：用构造出来的样本验证
「干净的不误报、多一个 `0x00` 能检出、`valLen` 写大能检出」——
不然「扫不到问题」到底是真干净还是检测失效，说不清。

### 卡组从哪来

「牌组」抽屉是**一个列表，按来源分组**：

| 分组 | 内容 | 能做什么 |
|---|---|---|
| **草稿** | `projects/*.json`，还没打包进游戏 | 编辑、保存、导出文本牌表 |
| **自制** | 自己打的包（`DATA_DLC_1M_*`） | 双击**直接编辑**，可删 |
| **系统自带** | 战役用的那批，**82 副** | 双击**直接编辑**（先弹提醒） |
| **社区包** | 别人做的包，**40 副** | 双击**直接编辑** |

每行右边是这副牌的**封面**（游戏里的牌盒贴图），左缘 30% 溶图渐变融进行背景。

贴图原图是 512×512 的 **3D 盒子渲染**（四周透明留白 + 左边一条盒脊），
后端裁两步：先取正面 `(203,92,162,256)`，再取上面 **40%** → **162×102**（比例 1.59）。
整块竖着铺只有 26px 宽太窄，截到 40% 有 66px，醒目得多。
比例在 `paths.RC_DECKBOX_FRONT` / `paths.DECKBOX_CROP_TOP` 调，
**前端用的是 `<img h-full w-auto>`，宽度跟着图片自身比例走**，改后端不用动前端。

### 新建 / 复制

顶部两个按钮：

- **新建** —— 左边填个名字，回车或点按钮，得到一份空工程
- **复制** —— 点一下进入**复制模式**，列表提示「在下面点一下要复制哪副牌组」，
  然后**单击**任意牌组就把它复制成新工程并直接打开

复制**不改原牌组**：游戏牌组走 `import` 落成独立工程，草稿走 `duplicate` 复制文件。
id 和名字都会自动加后缀防撞（`世界之树` → `世界之树-2` / `世界之树 副本`），
**连点多次不会互相覆盖**。

> [!NOTE] 为什么是单击不是双击
> 双击是「打开」。复制模式里改成单击，两个动作不会互相误触。

游戏牌组是**从 WAD 实时扫的**（走指纹缓存），不是本程序建的 —— 所以你装了什么包就有什么牌组。

### 两类保存，别搞混

| 按钮 | 写去哪 | 适用 |
|---|---|---|
| **保存草稿** | `projects/<id>.json` —— **游戏不认这个格式** | 草稿 |
| **构建** | 做成 WAD，**直接装进游戏目录** | 草稿 |
| **写回游戏包** | **直接改写游戏里的 WAD** | 双击打开的游戏牌组 |

### 构建：把卡组做成游戏能加载的包

「保存草稿」只是存工程文件，**游戏读不到**。要让游戏认，得点旁边的 **「构建」**：

```
① 选封面        从这副牌组里点一张卡 → 右边实时预览合成后的牌盒
② 选立绘        再点一张 → 预览四张贴图（头像 / 未解锁 / 背板 / 全身）
③ 打包          体检 → 打包并装入
```

**选卡范围是这副牌组自己的卡**（含解锁表），不是整个卡池 —— 两万多张里搜没有意义，
封面要的是这副牌的"招牌"，而招牌一定在牌表里。列表**按张数降序**排，
4 张的排在前面。一般也就 14~26 种，一眼扫完。

**两张图都走 Deck Builder 的原版合成管线**，不是自己画：

| 产物 | 素材 | 矩形 |
|---|---|---|
| 牌盒封面 512² | `D14_DeckBox{Mask,Overlay,Alpha}.png` | `(150,93,216,257)` |
| 圆形头像 256² | `D14_Personality{CircularMask,CircularAlpha}.png` | `(38,38,180,180)` |
| 大厅背板 256×512 | `D14_PersonalityBackplateAlpha.png` | `(0,0,256,512)` |
| 全身立绘 1024² | 无遮罩 | `(0,0,512,512)` |

四张立绘**全从你选的那一张插画派生**（未解锁头像是自动压暗去饱和）。
预览走 `/api/preview/*`，和打包时**逐像素一致**，不是示意图。

### 命名规则

**一个名字走到底**：卡组叫什么，包就叫什么，文件就叫什么。

```
卡组名「深海王座」
   │  pypinyin 转拼音、大写、只留 A-Z0-9
   ├─→ 包名 / WAD 文件名   DATA_DLC_SHENHAIWANGZUO.wad
   ├─→ XML 文件名          DECKS/SHENHAIWANGZUO.XML
   ├─→ 封面贴图            SHENHAIWANGZUO_BOX.TDX
   └─→ 立绘贴图            SHENHAIWANGZUO_PW{,_locked,_Backplate,_full}.tdx
```

### 游戏里显示的名字

**必须是 ASCII，不能用中文。** 那一栏的字体**没有中文字形**，写「深海王座」
游戏里渲染成 `[····]`（真见过）。官方牌组名也全是英文（`Sliver Hive`）。

优先级：`name_en` → `name_cn` → 拼音，前两个都要求是 ASCII 且不像内部标识：

```
深海王座   name_en="Throne of the Deep"  →  [Throne of the Deep]
Sliver Hive name_cn="Sliver Hive"        →  [Sliver Hive]
（都没有）                                →  [SHENHAIWANGZUO]   ← 拼音兜底
```

英文名从**旧包的简介前缀**里恢复（`（Throne of the Deep）一张牌就是一堵墙…`），
`to_project` 复制游戏牌组时也按这个规则取。

> [!IMPORTANT] TEXT 的 Ident 必须等于 **XML 文件名**
> ```
> DECKS/SHENHAIWANGZUO.XML          文件名叫这个
> name_tag="SHENHAIWANGZUO"         ← 必须是它
> TEXT 表 Ident="SHENHAIWANGZUO"    ← 也必须它，值写 [Throne of the Deep]
> ```
> 实测官方 `DECKS/D14_SLIVERS.XML` + `name_tag="D14_SLIVERS"` + TEXT `Ident="D14_SLIVERS"`。
> 早先这里用**包名**（`DATA_DLC_1M_DECK3`）当 `name_tag` 和 TEXT 的 Ident，
> 和文件名对不上 —— 游戏查不到就退回显示**文件名**，
> 用户在游戏里看到 `D14_1M_THRONEOFTHEDEEP` 就是这么来的。

### 解锁表

游戏里的「已解锁 / 锁定的」那 30 张牌，在包内是 `UNLOCKS/<名>_UNLOCKS.XML`，
靠 **`<UNLOCKS deck_uid="…">`** 关联到牌组 XML 的 `uid` 属性。

> [!NOTE] 大部分官方牌组**根本没有**解锁表
> 82 副「系统自带」里只有 **13 副**有：uid 1–10 那十副**玩家牌组**
> （Chandra / Dimir / Jund / Garruk / Humans / Jace / Liliana / Ramp / Slivers / Ajani）
> 加上 `DECK_2000_DB` / `DECK_2007_DB` / 女王包。
> 其余 69 副是 `D14_SEALED_*`（封印牌池）、boss 牌组、遭遇战 —— 不走解锁流程。

复制游戏牌组时（`to_project`）会把解锁表一起带过来；不带的话重新打包后

> [!IMPORTANT] 三处必须是**同一个字符串**，否则游戏显示文件名而不是中文名
> ```
> DECKS/SHENHAIWANGZUO.XML          文件名叫这个
> name_tag="SHENHAIWANGZUO"         ← 必须是它
> TEXT 表 Ident="SHENHAIWANGZUO"    ← 也必须它，值写 [深海王座]
> ```

> 和文件名对不上 —— 游戏查不到就退回显示**文件名**，
> 用户在游戏里看到 `D14_1M_THRONEOFTHEDEEP` 就是这么来的。

> [!WARNING] 为什么必须转拼音
> 游戏按名字查资源，**中文和标点会找不到**。所以文件/贴图名只能是 ASCII。
> `DATA_DLC_` 前缀保留（`DATA_DLC_D240` / `DATA_DLC_KEV` / `DATA_DLC_TFM_*`
> 都是这个约定），但**不再夹 `1M_`** —— 那是开发者的代号。
>
> 早先的写法是 `D14_1M_<name_en 去符号>`，中文名会被整个抹光，
> 出来 `D14_1M_THRONEOFTHEDEEP` 这种东西 —— 游戏界面上真会显示它，
> 用户看着一脸问号。

需要 `pypinyin`（`pip install pypinyin`）。没装也不崩：英文名照样能转，
中文名会退化成 `DATA_DLC_DECK`，日志里有警告。

### 一个包长什么样

```
<UID>/DATA_ALL_PLATFORMS/DECKS/<名>.XML              牌组定义（<CARD> + LandConfig 补地）
<UID>/DATA_ALL_PLATFORMS/DECKS/<名>_LAND_POOL.XML    可用基本地池
<UID>/DATA_ALL_PLATFORMS/UNLOCKS/<名>_UNLOCKS.XML    解锁表（恒 30 条）
<UID>/DATA_ALL_PLATFORMS/TEXT_PERMANENT/<名>_TEXT.XML 牌组名/描述（多语言表）
<UID>/DATA_ALL_PLATFORMS/AI_PERSONALITIES/<名>_PW.XML 鹏洛客人格（指向立绘）
<UID>/DATA_ALL_PLATFORMS/ART_ASSETS/TEXTURES/DECKS/<名>_BOX.TDX
<UID>/DATA_ALL_PLATFORMS/ART_ASSETS/TEXTURES/PLANESWALKERS/<名>_PW{,_locked,_Backplate,_full}.tdx
<UID>/HEADER.XML                                      容器头
```

**包只装牌组定义，不装卡。** `<CARD name="...">` 写的是卡的 `<FILENAME>`，
运行时由引擎去当前载入的内容包里找 —— 所以包**不硬绑定**任何卡包。

> [!IMPORTANT] 打包前的体检（`plan()`）
> 只有一条是**硬拦**的：**`<CARD>` 条数 + `sum(min*)` 不能超过 60**。
> `min*` 是引擎补地的**下限**，超过 60 就塞不进去了。
>
> 反过来**小于 60 是正常的** —— 引擎会把差的地补满到 60。
> 官方 `D14_SLIVERS` 就是 `59 张 + 引擎补 1 张`，而且它**压根没有 `<LandConfig>`**。
> （早先抄 dotp2014decks 按「必须正好 60」+「必须有 min*」一刀切，把官方牌组的副本全拦死了。）
>
**不满 60 张不提示也不拦** —— 那是引擎的正常工作方式，不是问题。
只有两条**提醒**（不拦）：牌表不足 60 且用了某色却没写 `min*`、解锁表超过 30 条。
>
> `uid_num` 三处（`base` / `+100000` / `+200000`）自动避让，不用操心。

装进去之后，**进游戏要手动进牌组编辑器「保存一次」**才算可用。

「写回游戏包」是**覆盖原牌组**，不是复制。所以：

- **自制包**直接写
- **系统自带 / 社区包**写的时候会**弹警告**（列清后果），确认后才写

### 两道警告，管的是两件事

| 时机 | 拦谁 | 说什么 |
|---|---|---|
| **双击打开时** | 只拦**系统自带** | 「修改系统卡组可能破坏游戏战役体验」—— 战役里对手用的就是这批牌，官方难度曲线按原牌表配的。**打开本身不动任何文件** |
| **点「写回游戏包」时** | 系统自带 + 社区包 | 这是**不可逆的覆盖**，会列清后果（所有存档可见、重装包就没了），并提示会自动整包备份 |

社区包**打开时不拦** —— 它跟战役无关，只在真正要覆盖原作者内容时提醒。

写回的安全机制见下面「直接改写 WAD」一节。

## 关键设计

### 1. 卡面用 **DOM 分层合成**，不是位图

参考实现（C# 的 DotP 2014 Deck Builder）是用 GDI+ 把牌名和规则文本**画进位图**，
输出一张 356×512 的 `Bitmap`。**我们没有这么做**：

```
第 1 层  <img> 插画        铺满整张
第 2 层  <img> 卡框        中心镂空，插画从下面透出来
第 3 层  HTML 文本         牌名 / 类型行 / 规则文本 / 力防
第 4 层  <img> 符号        费用串、系列稀有度符号
```

**为什么值得**：文字保持矢量 → 悬浮放大后**依然锐利**（位图放大会糊）、能选中复制、
换中文字体不用重做素材，而且**不必为 2.2 万张卡各生成一张合成图**
（只要 162 张卡框）。

卡框镂空是**实测过**的：`DATA_CORE.WAD` 的 `W.TDX` 头写 512×356（横放），
转 90° 成竖版后，插画窗口 `(16,47,324,238)` 区域 alpha **全是 0**。

排版坐标来自 `CardInfo.cs:79-107` 的 Rectangle 常量表，全部换成百分比，任意尺寸等比缩放。

> 外部调用者（脚本 / agent）不想要浏览器时，用 `render.py` —— 同一套坐标，
> 用 PIL 渲染成 PNG。见 [`API.md`](API.md)。

### 2. **不做虚拟滚动**

从参考项目 phase 学到的：它 2 万多张卡一点不卡，靠的不是虚拟列表，而是
**搜索结果限流**（默认 175 条一页）+ `loading="lazy"`。
DOM 里同时存在的卡片节点永远只有一页。

需要更多就滚到底自动加载下一页。比虚拟滚动简单得多，而且已被验证有效。

### 3. 低内存读 WAD

`dotp2014decks` 的 `Wad.__init__` 是 `self.raw = f.read()` —— **整个文件读进内存**，
`deck_note.Art()` 因此常驻 **4.03 GB**；`cover.load_art()` 更是每取一张图就重开一个 100MB 的包。

本项目用 `wadlite.MMapWad`（`self.raw` 换成 `mmap`，`_parse()` 全程只读所以直接继承）
+ `WadPool` 句柄 LRU。打开 172MB 的包不再吃掉 172MB 常驻。

**自检**：`python backend/wadlite.py` 会拿 77 个包逐一比对 mmap 版和原版的解析结果 —— 全一致。

### 4. 缩略图磁盘缓存

解码一张 512×376 约 8ms，2.2 万张 ≈ 3 分钟纯 CPU。所以按需生成、落盘、二次访问直接读文件。

- 256px WebP，一张约 **4~10KB** → 全量约 180MB
- 分片存放（`thumbs/<两位哈希>/`），不把 2 万多个文件堆一个目录
- 先写临时文件再改名 —— 半截文件被读到会让浏览器缓存坏图

### 5. 直接改写 WAD —— 四条保险

把改动写回游戏包是**不可逆的覆盖**，所以下了四道闸（`deckwrite.py`）：

1. **必须走 `Wad.rebuild()`，不能重新打包。**
   `dotp2014decks` 在这上面踩过大坑：用「按路径重新搭树、从头打包」的写法，
   会丢掉 WAD 头部的 `headerXml`（内容包声明）和空目录 ——
   后果是**游戏启动后变英文、中文全渲染成 `•`**（文本加载了，中文字体没加载）。
   `rebuild()` 把头部 + dataOffsets 数组 + 文件表**逐字节原样复制**，只重写变动的条目。

2. **写前自检**：先跑一次 `rebuild({})`，必须能字节级还原原文件。
   还原不了说明这个包的布局有 rebuild 处理不了的东西 → 中止，原文件不动。

3. **整包备份**：写到 `data/backups/<包名>.<时间戳>.bak`，出了事直接拷回去。

4. **只做外科手术**：只替换 `<CARD>` 列表和 `<LandConfig>`，
   `<DECK>` 上的全部属性（uid / content_pack / personality / steam_id…）
   和 `<DECKSTATISTICS>` 原样保留 —— 重新生成容易漏字段。

另外会检查**数据块是否被多个条目共用**，共用就不能单独改（会波及别的条目）。

### 6. 错误处理导向「能查」

- 落盘 `data/logs/app.log`（5MB × 3 轮转）
- 内存环形缓冲最近 300 条 WARNING 以上，带 traceback → 界面的「诊断」面板读它
- `sys.excepthook` / `threading.excepthook` 兜底，未捕获异常也一定进日志
- HTTP 错误结构化：`{ok:false, error:{type,msg,where,hint,trace}}`，
  `hint` 是「这个错通常意味着什么」
- `log.guard()` 装饰器：单张卡坏了不拖垮整批

## 踩过的坑（都修了）

| 坑 | 说明 |
|---|---|
| **PT 框按目录找只捞到 1 个** | 9 个 `PTBOX_*` 里只有 `PTBOX_W` 在 `MODELS/CARD/` 下，其余 8 个在 `TEXTURES/` 根。改成按文件名为准、目录只用来消歧 |
| **插画索引的 XML 分支进不去** | 循环开头有 `if not up.endswith(".TDX"): continue`，把后面的 XML 分支一起跳过了 → 22,000 张卡全部「没写 ARTID」。把 TDX 判断并进分支条件 |
| **`FORMAT` 里混着系列名** | `value="Eldritch Moon"` 是「这个系列内的合法性」，不是赛制。加了白名单过滤，否则筛选器里冒出一堆系列名 |
| **关键词中文名学不出来** | 自动学习只能覆盖 21 种，且卡池里有些卡没汉化会把英文名学进来。改成 35 条手工表打底 + 自动学习补充（且优先含中日韩字符的） |
| **统计口径写错** | 把「`<CARD>` 条数 + `min_lands` 之和」当成了总张数。实际引擎的规矩是「`<CARD>` 条数 + 补的地 = **60**」，`min*` 只是下限 |
| **`UnboundLocalError` 吃掉 3792 张卡** | 编辑时循环外留了一行引用未定义变量，被 `guard` 吞了。教训：批量处理的异常计数要打出来看 |
| **`bytes == mmap` 恒为 `False`** | CPython 里 `mmap` 和 `bytes` **永远比较不相等**，哪怕逐字节一致。写回前的自检 `rebuild({}) != src.raw` 因此每次误判失败，**所有写回都被拒**。改用 `memoryview` 比（不复制内存） |
| **FastAPI 贪婪路由顺序** | `{deck_id:path}` 会吞掉 `/writable` `/save` `/import` 这些子路由。通用路由**必须注册在最后**，否则子路由永远进不去 |
| **官方基础牌组用 `@N` 合并写法** | `SHOCK_348966@2` 是「2 张 Shock」，不是卡名。不解后缀的话卡名对不上卡池、张数也少算。注意解锁表里的 `@N` 是**洗牌偏向**，不是一回事 |
| **牌组名不在自己的包里** | `DATA_DECKS_D14.WAD` 里**一个 `TEXT_PERMANENT` 都没有**，官方牌组名全在中文包 `DATA_DECKS_D910.WAD` 里。按包各查各的会全军覆没，得建跨包的全局文本表 |
| **文本表 `<Row>` 带属性** | 实际是 `<Row ss:AutoFitHeight="0">`，正则写成 `<Row>` 一条都匹配不上 → 牌组名全退化成 `D14_JUND` |
| **文本表取错列** | 表头是 `Ident \| Comment \| Master Text`，名字在**第 3 列**。取第 2 列会拿到 uid 数字（D240 的表里就是 `240`） |
| **`/DECKS/` 下混着非牌组文件** | D240 的 `ELDRAZI2~8.XML` 是鹏洛客 CONFIG（341 字节），不是牌组。得靠有没有 `<DECK>` 标签来认 |
| **导入游戏牌组后卡片信息不加载** | 导入接口只回牌表（英文卡名），不带卡的详情。不额外拉一次的话，牌组面板会显示英文名、类型归到「其他」、卡面画不出来 |
| **「仅限」改了三轮才对** | ①`cset <= plain_colors`（颜色子集）→ 选黑白时单黑单绿也进来（用户看到的「万物元气兽」）；②`== plain_colors or not cset`（加无色）→ 4502 张神器/地淹没结果；③`== plain_colors` → **和「恰好」完全等价，成了死按钮**。现在走对路子了：**「仅限」= 混血** —— 读 `cost` 找混血符号，选 B+G 出 36 张 `{B/G}`/`{2/B}`/`{B/P}`，是「**或**」；「恰好」出 117 张金卡 `{B}{G}`，是「**且**」 |
| **窗口不能在子线程里 create/destroy** | 想做「启动小窗 → 后台建索引 → 换成主窗」，结果 Windows 上直接崩：`winforms.py:814` 的 `signal.signal(signal.SIGINT, ...)` 抛 `ValueError: signal only works in main thread`。pywebview 的 `start(func)` 把 func 放**子线程**跑，而它的 Windows 后端在 `create_window` 内部要调 `signal.signal()` —— 那个只能在主线程调。**且异常抛在子线程里，`webview.start()` 外层的 try 兜不住**，程序静默退出、日志里才有堆栈。结论：pywebview 窗口的创建/销毁全程只能待在主线程，建索引必须**同步建完再开窗** |
| **`focus` 被 `URLSearchParams` 静默丢掉** | 「拖回卡池删除后跳过去」靠 `/api/cards?focus=<key>` 定位。key 原先只从界面缓存 `cardCache` 里翻，而后端对「卡池里查不到的卡」会塞一条 `{key: 原始bag键, missing:true}`（`api.py` 的 `details()`），前端原样存 —— 于是缓存里能有 `key` 为 undefined 的条目。而 `URLSearchParams` 对 undefined **是静默忽略的**（`put()` 里 `v === undefined` 直接 return），`focus` 压根没发出去，后端 `focus or None` 拿到 None，`focus_index` 永远 null。**症状是「怎么筛都跳不过去」，而提示还赖在筛选头上**。现在加 `/api/cardkey?name=` 做权威来源，缓存只当快路 |
| **失败提示分不清两种原因** | 「不符合当前筛选条件」和「key 没送到」在界面上长得一模一样，查了半天。现在 toast 带上**命中数** —— 等于卡池总数说明没在筛（是 key 的问题），命中很少才是筛选挡的 |
| **同名草稿的 uid 会撞车** | `blank()` 里 `uid = DATA_DLC_ + 拼音(名字)`，所以两副都叫 `NEW` 的草稿 `uid` **完全相同**。`POST /api/decks` 原先只给 `id` 加后缀、不动 `uid` —— 后果是列表里几行都叫「NEW」分不出谁是谁，打包还会落到**同一个 WAD 文件名** `DATA_DLC_NEW.wad` 上互相覆盖。现在撞车时 **id、名字、uid 三个一起加后缀**。触发门槛被「新建改成一键、默认名 NEW」大大降低，才暴露出来。⚠️ 基准值要在循环**外**取，循环里读 `d["name_cn"]` 会每轮追加一次，三轮下来变成「NEW 2 3 4」 |
| **颜色模式 chip 藏起来 → 状态失联** | 三档 chip 曾经包在 `colors.length > 1 &&` 里，只在多色时出现。于是**从多色退回单色时 chip 集体消失，`color_mode` 却还停在 `only`** —— 用户看到「只选了 B 却只出混血牌」（B + only 只有 6 张），界面上没有任何线索说明为什么，只能判定成 bug。改成**三档常显**；没选颜色时这一档本来就不起作用（后端整个颜色块会跳过，`only` 会返回全池 21386），所以置灰并提示「先选一个颜色」。**教训：筛选条件必须一直可见，藏起来的控件会产生看不见的残留状态** |
| **混血符号不赋予颜色** | 这是上一条绕三轮的**根因**。数据里 `{B/G}{B/G}` 的 `colors` 是 `[]`，`{G/U}{W}` 只记 `['W']`，连 `{3}{G/P}` 的**诞生荚**（真卡是绿牌）都是 `[]` —— 全池 355 张带混血符号的卡都这样。**判据必须读 `cost` 字符串**，看 `colors` 永远分不出 `{B}{G}` 和 `{B/G}{B/G}`。副作用：这些卡在界面上大概率正拿着无色框渲染（待确认） |
| **「无色」筛选返回全卡池** | `any` 分支写的是 `if plain_colors and not (cset & plain_colors)`，而只勾「无色」时 `plain_colors` 是**空集** —— `if` 直接短路，**整段判色逻辑一次都不执行**。表现为「筛无色却混进一堆蓝牌」。改成逐桶取并集，并加了会**逐张验证**的自检（`python backend/cardset.py`） |
| **`os.replace` 偶发 WinError 5** | 报「拒绝访问」但**不是权限问题**。CPython 在 Windows 上打开文件不带 `FILE_SHARE_DELETE`，所以**任何并发读都会挡住替换** —— 而前端每次操作后都刷牌组列表，正好撞上。5 次里中 1 次。统一走 `fsx.write_*` 小步重试 |
| **`uid_num` 会分到同一个号** | `used_uids()` 建一次就缓存，打完包不登记的话，连着打包两副牌都拿到同一个编号 → 包互相覆盖。现在「找到即登记」，另拆 `peek_uid_num()` 给界面预览用（不然每开一次向导烧一个号） |
| **`deck_box_image_locked` 写了张不存在的图** | 照抄时写成 `<封面名>_locked`，但根本没生成那张贴图。原版指向的是**游戏自带的** `D14_LOCKED.TDX` |
| **`✓` 把整个程序打挂** | Windows 控制台默认 GBK，`tools/*.py` 里带 `✓` `→` 的进度输出编码不了直接抛 `UnicodeEncodeError`。崩在**启动建索引**阶段，看着像程序坏了。`log._utf8_console()` 把 stdout/stderr 拧成 UTF-8 |
| **打出来的包游戏静默忽略** | `wadbuild.build()` 漏了 `header_xml` 参数 → 容器头 **0 字节**，没有内容包声明，游戏**不报错也不加载**，就是"没读到"。现在 `_verify()` 会把字节读回来核 headerXml / 根名 / 条目数，不合格直接抛 |
| **复制卡组会拿到同一个包名** | `duplicate()` 从 `d["id"]` 推 uid，中文 id 被 `[^A-Z0-9]` 抹光后只剩个位数，两份工程撞同一个包名 → 谁后打包谁覆盖谁。改成从名字转拼音 + 查重加后缀 |
| **`safe_uid_part` 会毁掉包名** | 它把下划线也当非法字符，`DATA_DLC_1M_DECK3` 被毁成 `DATADLC1MDECK3`。包名允许下划线，得单独一个只挡中文和标点的清洗 |
| **`<CARD>` 条数不等于牌组张数** | 打包时 `<CARD>` 条数 + `min_lands` 之和**必须正好 60**，多一张少一张都不行。界面上看着「50 条牌」其实要配 10 张地 |
